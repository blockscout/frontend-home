# Phase 1 usage log

Every miss in daily use of home, for the two weeks that gate phase 2
([blockscout/frontend#3882](https://github.com/blockscout/frontend/issues/3882)). One line per miss, added
when it happens.

| Date | Kind | What happened | Fixed by |
|---|---|---|---|
| 2026-11-19 | Check | In a task worktree the child's spell check checked 0 files and passed, in `pnpm lint:cspell` and in the pre-commit hook. cspell's `useGitignore` applied home's `.gitignore`, which ignores `/.claude/worktrees/`. The main clone's child was not affected (3625 files), nor was CI. `--no-must-find-files` hid the empty run. An audit of the child's other checks in a task worktree (eslint, tsc, vitest, playwright, doc-links, react-doctor, ripgrep) found the same files as in the main clone. | Fixed by [blockscout/frontend#3913](https://github.com/blockscout/frontend/pull/3913): `gitignoreRoot` in the child's `cspell.jsonc`, and `lint:cspell` without `--no-must-find-files`. A second child that uses cspell needs the same setting. |
| 2026-11-19 | Tooling | In a task worktree the harness refused 11 compound commands that contained `git` (loops, `set -e` scripts, heredocs), across 6 sessions of one task. The refusal comes from Claude Code's guard for worktree sessions, which cannot verify that such a command stays inside the worktree. Not specific to home: it is Claude Code's worktree isolation check, which its [docs](https://code.claude.com/docs/en/worktrees) say cannot be turned off. | Fixed by [#12](https://github.com/blockscout/frontend-home/pull/12): a line in `AGENTS.md` under "Work in the active child". |
| 2026-11-19 | Skill | `implement-ticket` step 1 resolves the task folder from the branch `issue-<number>`. The home worktree's branch was `frontend-address-portfolio`; `issue-3855` was the child's branch. Cost: three calls to find the task. Five more child documents resolve a task from the branch the same way. | Fixed by [#12](https://github.com/blockscout/frontend-home/pull/12): a line in `AGENTS.md` under "Work in the active child", so the child's skills stay unchanged. |
| 2026-11-20 | Tooling | In a task worktree the harness refused a compound command that contained no `git`: one `python3` heredoc and two `cat > file <<'EOF'` heredocs chained with `;`. The message was "this command is too complex to verify that it stays inside the worktree". The line PR #12 added to `AGENTS.md` names only a loop, a script or a heredoc that contains `git`, so the refusal was not expected. Cost: one refused call, then a re-sent edit script that had already run and duplicated two declarations, caught by vitest in one cycle. One session, ticket 05 of blockscout/frontend#3855. Not specific to home: the same worktree isolation check, whose docs do not list the command shapes it refuses. | Fixed by [#13](https://github.com/blockscout/frontend-home/pull/13): the `AGENTS.md` line now asks for plain Bash calls, with no loop, script or heredoc whether or not it contains `git`, and for files written with the Write and Edit tools. |
| 2026-11-20 | Tooling | In a task worktree the Playwright MCP refused a screenshot path in the session scratchpad: "File access denied … outside allowed roots". Its allowed roots are the home worktree and the home worktree's `.playwright-mcp/`, not the child and not the scratchpad. Screenshots and page snapshots of the child's dev server therefore land in home's `.playwright-mcp/`. Cost: one failed call. `implement-ticket` Step 4 does not say where to save them. Not specific to home: the scratchpad is outside the allowed roots in a standalone clone too. | Fixed by [blockscout/frontend#3915](https://github.com/blockscout/frontend/pull/3915): a line in `implement-ticket` Step 4 to save screenshots under `.playwright-mcp/` with a relative path. |
